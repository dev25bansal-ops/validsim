## Execution pass 1 — benchmark gate made real (baseline committed)

The nightly benchmark gate was permanently vacuous: `tests/bench/baseline.json` had never been committed, so `--validsim-benchmark-compare` could only ever report "CANNOT MEASURE". Three independent defects had to be fixed to make it runnable:

1. **Budget was a lie** (`tests/bench/conftest.py`) — `_affordable_rounds` did `max(MIN_ROUNDS, min(rounds, budget // single))`, which has **no ceiling**: a 12 s call against a 3 s budget still ran 3 measured + 2 warmup ≈ 60 s. Replaced with the pure `plan_rounds(single_s, rounds, warmup, budget_s)`, which bounds the **total** call count (warmups included), sacrifices warmups before dropping below `MIN_ROUNDS`, and always takes ≥1 sample. Tests: `tests/bench/test_bench_budget_plan_agent.py`.
2. **Unbounded fixture cost** — `SqliteValidationStore.save` commits (fsyncs) per call, so seeding 100 000 rows measured ~15 min; the store-scale benchmarks seeded twice for identical data. Added `ValidationStore.save_many` (base: loop; SQLite: one transaction + `executemany`, ~300× faster — 100k rows in ~2.9 s). Benchmarks now share one seeded store/DB per size via module-scoped fixtures. Shared insert SQL factored into `_INSERT_SQL`/`_insert_params` so `save`/`save_many` cannot drift. Tests: `tests/test_store_save_many_agent.py`.
3. **BUG-003, zero baseline crashed the gate** — `compare_to_baseline` did `delta / prior` (and again inside the f-string), raising `ZeroDivisionError` when `prior == 0.0`. `memstore_count_n*` measures below timer resolution, so the committed baseline holds literal zeros and the crash was reachable. Now falls back to the absolute noise floor and prints "no baseline ratio".

**Result:** `tests/bench/baseline.json` committed with **55 benchmarks**; fast tier runs in **12m42s** (was 50+ min, and could not complete before). Gate verified three ways: identical → clean, 2× regression → reported, zero-baseline regression → reported without raising.

## Execution pass 2 — read-path immutability, wire contract, and the log-mute leak

### The memory store handed out live handles on READ (real, verified)
`ValidationStore` snapshotted on **save** (so the caller could not corrupt a
record) but returned the stored object by reference on **read**. A read handle
was therefore a window onto stored evidence: `get(run_id).episodes.clear()` took
a stored verdict to zero episodes, and `evaluation.per_task_success["t"] = 0.0`
changed the evidence behind an APPROVE with no write, no lock and no log line.
Verified live — the mutation stuck on the in-memory backend and did not on
SQLite (which rebuilds per read), so the two backends disagreed about whether
stored evidence could be rewritten.

Fix: **freeze on save instead of copy on save.** New `validsim/store/_frozen.py`
(`freeze()`) structurally rebuilds every mutable container reachable from a
record — `dict`→`MappingProxyType`, `list`→`tuple`, `set`→`frozenset`, nested
dataclasses via `dataclasses.replace` with `object.__setattr__` — and returns
the input unchanged when already frozen (so re-freezing is free). Reads then
share the frozen object with **zero** copy cost. `EpisodeResult` is now a frozen
dataclass, which is what makes the freeze total rather than one level deep.

Because reads are now shared rather than copied, the store *refuses* mutation
where SQLite *accepts-and-discards* it on a private copy. Both leave the store
returning the original; the new suite asserts on the store, never on the handle,
so it cannot pass by asserting the wrong thing. New
`tests/test_store_read_immutability_agent.py` (50 tests, every leak vector on
every backend). Benchmark gate re-verified after the change: **all benchmarks
within tolerance**, so the freeze costs nothing measurable.

### BUG-004: `logging.disable` leaked process-globally (root cause of 6 failures)
`tests/test_api_obsstats_agent.py` called `logging.disable(logging.CRITICAL)`
bare inside two benchmark bodies. `logging.disable` is **process-global and
sticky**: it raises the floor for every logger in the interpreter and stays
raised until something lowers it. Six tests in three other files failed in the
full suite and passed in isolation, all with an empty capture list —
`test_jobs_claim_deadletter_agent` (×2), `test_jobs_worker` (×2),
`test_logging_redaction`, `test_metrics_content`. Every one of them asserts on a
log record, and the record was discarded by `isEnabledFor` before any handler ran.

Fix: `_quiet_logs()` context manager saves `logging.root.manager.disable` and
restores it on exit (so a host's prior mute is preserved, not clobbered), plus
`TestLogMutingDoesNotLeak` pinning the property rather than the symptom.
