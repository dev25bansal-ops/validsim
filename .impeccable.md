# Design context — ValidSim marketing site

Established 2026-09-30. Required by the Impeccable skill before any design work;
recorded here so the reasoning survives future sessions and reviewers.

## Purpose

A single landing page whose job is to make a **robotics foundation model engineer**
or a **Techstars reviewer** understand in ten seconds what ValidSim is, believe it
is real, and start a conversation.

It is not a product page. The product is the operator dashboard, already built and
already good. This page has exactly one job: earn the next conversation.

## Audience, in priority order

1. **Techstars Founder Catalyst reviewers.** They screen many applications and are
   checking for engineering judgment and honesty, not feature lists. They have
   already read our application answers, which lead with "we built the engine
   before our first customer conversation." This page must be consistent with that
   or the disconnect is worse than saying nothing.
2. **Robotics ML engineers** at foundation model labs. Senior, skeptical, allergic
   to marketing language. They will look for the actual output format.
3. **Fleet operators / enterprise** (12-18 months out). Secondary; the page must
   not over-claim for them yet.

## Use cases

- Skim for five seconds, grasp the category, keep reading.
- Inspect the artifact and confirm the numbers are real (the terminal transcript).
- Find the contact path.
- Check for signs of an over-claiming founder - and find the opposite.

## Brand personality

**Precision instrument.**

ValidSim is a measurement device that stands between a model and a fleet. The
design should feel like the equipment that produces evidence - an oscilloscope, a
flight recorder, an engineering drawing - not like software that glows.

Three commitments, in order of importance:

1. **Evidence over claims.** Every number on the page came from running the tool.
   Where something is a target rather than a measurement, it is labelled as one.
2. **Confident, not apologetic.** We are pre-traction and say so once, plainly,
   then spend the rest of the page on what we have actually built.
3. **Restraint with one dramatic moment.** Bold means one unforgettable focal
   point, not effects everywhere.

## Aesthetic direction

**Instrument panel, spec sheet.** Chosen deliberately over the default "dark
developer tool" look, which is the most over-produced aesthetic on the web now.

Concretely:

- Near-black chassis, but **no ambient glow**. Light comes from the readout, the
  way a backlit instrument is lit by its own display, not by a lamp behind it.
- **Verdict is the colour system.** Green = APPROVE, red = BLOCK, amber =
  unmeasured. The palette is not decorative; it is the product's semantics. The
  page's accent is the same colour that appears in the transcript.
- **Engineering-drawing texture** (graph grid), not noise, not glassmorphism.
- Typography carries the personality: a technical grotesque with real character,
  not Inter/Roboto/system-ui. Monospace is reserved for *actual data* - run ids,
  scores, figure numbers - never as lazy "developer" decoration.
- Asymmetric layout with genuine scale jumps. Not centred-everything.

## Hard constraints

- **WCAG AA minimum.** Body text >= 16px, real focus states, full keyboard
  operation, no colour-only meaning (verdicts always carry a word).
- **Prefer no build step.** No framework, no bundler, no node_modules. A static
  file that cannot break is worth more here than a toolchain.
- **Motion must be optional.** Scroll animations behind `@supports`, and disabled
  entirely under `prefers-reduced-motion`.
- **Dark only.** Matches the operator dashboard; a half-finished light theme is
  worse than none.
- **The live operator dashboard is untouchable.** This site is a separate file.

## Anti-goals - what this page must never become

- Cyan/purple gradient hero. The most over-produced look on the web.
- Glassmorphism, or frosted panels used decoratively.
- Neon glow as a substitute for hierarchy.
- Emoji as iconography.
- Icon-in-a-rounded-square above every heading.
- Cards for everything, including things that should be plain text.
- A centred column with everything centred inside it.
- Any claim not produced by running the software.
